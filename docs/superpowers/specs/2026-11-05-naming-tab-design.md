# Naming tab: automatic structure names for Web, HP and BS — design (2026-11-05)

## Why

The engineer needs names on the panel structure to make 2D drawings later. Today the drafter writes them by hand as
Text next to the X-X / Y-Y sections (CAS.dump.json, panel 7D-16C). This stage only produces and edits the names
inside the tool. Using them on drawings is a later stage (non-goal here).

## How the drafter names 7D-16C (analysis of CAS.dump.json)

| Name | Member | Runs along | Counted |
|---|---|---|---|
| T1…T7 (+T6a) | Web (AM_0) | Y | left → right |
| L1…L4 | Web | X | bottom → top |
| HT1, HT2 | HP (AM_3, colour 30) | Y | left → right (edge HPs) |
| HL1…HL18 | HP | X | bottom → top |
| BS | Flat bar 80×6 | either | no number |

One name covers a whole line: T3 is four web pieces cut by L1 and L2. T6a is a web the drafter inserted between T6
and T7. Rules cannot guess that, so the user renames it.

## Decisions (engineer, 2026-11-05)

1. A separate **Naming** tab (after Result). Not a column on Result.
2. Names are **generated by rule**. They will sometimes be wrong; the user renames them on the grid, like Result.
3. **One name per line**: every collinear piece, including pieces of a different thickness.
4. HP 1B2E9 on line L3 **belongs to L3**.
5. Every flat bar is named **"BS"**.
6. Members with no label stay **blank** (they don't appear on the grid).
7. Numbering follows the **ship direction**, as a fixed rule per panel position:
   - T / HT: from aft to fore, the bow is at X+ ⇒ left → right.
   - L / HL: from centre line to side. Port: bottom → top. Starboard: top → bottom.
   - Center: bottom → top (**my call**, matches 7D-16C; the engineer did not object).

## Approaches

- **1. Standalone Naming tab (chosen).** A "Select panel" button runs 2D classification only (no 3D). The tab is also
  refreshed after Build 3D / rebuild / Load 3D. Names can be set before any 3D exists, which suits a 2D-drawing goal.
- 2. Naming fed only from Build 3D results, like Result. Rejected: the user would have to build 3D just to name parts.
- 3. A Name column on Result. Rejected by the engineer (separate tab).

## Design

### Lines
- Members: Web and GirderEnd (web ends) are "Web"; HP is "HP"; FlatBar is "FB". Other kinds are not named.
- Geometry is taken in the **2D block's own frame** (inverse of the block transform), so moving or rotating the
  block does not change names.
- Direction: the axis nearest to the member's long axis (diagonal members go to the nearest axis).
- Web and HP pieces with the same direction whose centre lines are within **15 mm** belong to one line. They don't
  need to touch.
- Line kind = the kind (Web or HP) with the larger total length. Every Web/HP piece on the line gets its name
  (so HP 1B2E9 gets L3).
- FB pieces are never merged with Web/HP. Each FB row is one flat bar line (collinear FB pieces split at HPs are one
  row), always named "BS".

### Auto names
- Four counters: `T#` (Web along Y), `L#` (Web along X), `HT#` (HP along Y), `HL#` (HP along X).
- Order by the line's centre coordinate: T/HT by X ascending; L/HL by Y ascending (Center, Port) or descending
  (Starboard).

### Grid
- Columns: **Name** (editable), Kind (Web/HP/FB), Dir (T/L), Pieces, Length (total, mm), Thickness / spec, ⌖ zoom.
- Click highlights every piece of the line. Multi-select, Ctrl+C and context menu **Reset to auto** work like
  Result. Typing a name on a row in the selection gives every selected row that name.
- Highlight uses the 3D solids when the panel came from a build, else the 2D polylines. ux-guardrails rules apply
  (several drawings, no silent failures, Cell* styles).

### Storage
- Only **user-edited** names are stored, per piece (SourceKey), in a new XRecord `MCG3D_NAMES` on the 2D block
  definition (saved with the drawing, like corrections). Renaming a line writes the name to all its pieces.
- Auto names are recomputed on every load, so inserting a web shifts the numbers while hand-typed names stay.
- A line whose pieces carry different stored names shows the most common one. An empty name = back to auto.
- Renaming never triggers a rebuild.

### Testing
- The line grouping, ordering and naming live in pure C# (`Naming/StructureNaming.cs`), unit-tested on
  7D-16C coordinates: expect T1…T7 (T6a comes out as T7, T7 as T8 — the user renames), L1…L4 with HP 1B2E9 in L3,
  HT1–HT2, HL1…HL18, BS; Starboard reverses L/HL; a stored name overrides the auto name.
